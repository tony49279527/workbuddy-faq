企业管理后台能做什么

企业版管理后台的安全管控能力全览 —— 12 个分区、37 个功能页，逐页梳理
整理日期：2026-10-09  |  后台地址：www.codebuddy.cn/admin
口径来源：企业版管理后台实际页面（2026-10-09）

0. 一句话先说结论

企业版后台一共 12 个模块分区、37 个功能页。但对财务部门真正「管得住人、管得住数据」的， 其实就集中在 4 个地方：

  1. 安全中心 → 客户端安全：唯一能真正约束「成员在电脑上能用 AI 干什么」的地方（能读哪些文件、能跑哪些命令、能连哪些网、能不能开完全访问）。这是对财务最关键的一页。
  2. 企业设置 → 网络设置（IP 白名单）：把登录锁在公司出口 IP 上。
  3. 客户端配置 → 分享与协作：防止财务数据被一键发布到公网。
  4. 日志管理 → 对话日志：合规审计留痕（有前置条件，见第 4 节）。

其余的模块，主要是分配账号、控制成员能用哪些 AI 能力（模型/技能/专家/连接器）、看用量花销， 属于「资源治理」和「成本管理」，安全属性相对弱一些。

  1. 后台全貌：12 个分区、37 个页面
  2. 账号与权限：怎么发账号、怎么分权
  3. 安全中心（重中之重）
  4. 数据边界与合规
  5. 资源治理：控制成员能用哪些 AI 能力
  6. 用量与成本控制
  7. 财务部门落地配置清单（推荐值）

2. 账号与权限：怎么发账号、怎么分权

2.1 成员与部门 /admin/member/list

关键点：这一页是「只读」的。
页面明确写着：「数据来源于统一身份（OneID）」「成员与部门变更请前往 OneID 管理后台完成；本页提供只读浏览与授权管理。」
也就是说——加人、减人、改部门，不在这里做，要去「腾讯统一身份」平台做，做完自动同步过来。 这里只能做两件事：授权客户端 / 取消授权。

对企业管理员来说，这就是「分配账号」的真实链路：

  1. 去腾讯统一身份（OneID）平台 → 把员工加进企业通讯录、划好部门；
  2. 回到本后台 →「成员与部门」里给该成员授权客户端；
  3. 回到「订阅管理」→ 确认席位够用（席位是有限资源，需按实际人数配置）。

页面顶部还有一步引导：「成员添加完成后，可分配成员许可证。分配完成后成员可使用客户端。」

2.2 成员审核 /admin/member/qualification

处理成员自己发起的加入申请。分「待审核 / 已审核」两个页签，操作有三档：

  • 通过并分配席位（一步到位：批准 + 给席位）
  • 仅通过（批准但不给席位，需再单独授权）
  • 拒绝

列表字段：ID、姓名、成员来源、邀请人、申请时间、操作。

2.3 管理员角色 /admin/member/role

权限分级的地方。预置一个「超级管理员」角色（具备后台管理所有权限），可以：

  • 添加角色：自定义角色，按需给权限（不必人人都给超级管理员）
  • 添加超级管理员：把某人设成超管
  • 移除角色
财务部门的用法建议：财务同事一律给普通成员，不要给管理员。 如果确实需要一个「财务侧对接人」来管本部门的策略和用量，再单独建一个受限角色给他，而不是直接给超管。

3. 安全中心（重中之重）

3.1 综合管理 /admin/security/general

定位是「企业安全相关的所有管控开关统一入口」。目前「AI资产」下有一个开关：

开关说明
技能安装安全
客户端禁止安装高风险技能		 开启后，端侧导入技能时若安全检测判定为高风险则禁止安装，且不可跳过检测直接安装；关闭则允许安装。
（建议开启。技能/插件是外部代码，是数据外泄的一条隐蔽通道。）

3.2 客户端安全 /admin/security/client

先看「适用产品」范围

产品是否支持
CodeBuddy（IDE / VS Code / JetBrains 插件）暂不支持
WorkBuddy（桌面端）支持
企业智能体暂不支持

页面原话：「用安全策略统一约束成员在客户端可以做什么：能读写哪些文件、能执行哪些命令、能访问哪些网络、以及是否开放内置运行时。为不同部门或成员创建不同策略，即可按需收紧或放开。」

三条机制，先记住

  1. 企业策略是「底线」：下发的策略在客户端作为企业底线，成员可以在此基础上叠加更严格的个人配置，但不可突破企业策略的限制。
  2. 多策略命中，只生效一条：当一名成员同时命中多条企业策略时，只有优先级数字最大的那一条整体生效（数字越大优先级越高）。
  3. 生效有时效：策略保存/启停后，成员重启客户端立即生效；不重启则由客户端按约 10 分钟周期自动同步。

新建一条策略，能配什么

点「新建策略」进入配置页，分 基本信息 + 4 个配置分页 + 生效范围：

分页配置项作用与细节
沙箱安全 沙箱安全总开关 关闭后，文件保护 / 命令控制 / 网络访问三模块规则全部不生效。
允许对话内开启完全访问 关闭后，成员无法在客户端对话里切到「完全访问」模式，所有操作强制在安全沙箱约束内。
该配置独立于沙箱总开关与下方的文件/命令/网络规则，互不影响。
安全规则（按路径配置） 每条路径可对 读 / 写 / 删除 分别设置 允许 / 询问 / 禁止；列表靠前的规则优先生效。
命令规则（按前缀配置） 按前缀匹配（空格切分），如「git push」匹配以 git push 开头的命令；列表靠前的规则优先生效。
网络访问 可配「禁止全部对外访问」+ 例外白名单：「禁止全部对外访问」时，例外白名单外的域名一律拦截。
数据安全 删除保护 文件删除的保护开关。
批量删除审批阈值 单次删除文件数超过该阈值时需审批。
内置运行时 总开关 + 工具清单 工具清单含：Node.js、Python、Git Bash、Brokered Shell。不需要跑脚本的岗位可以直接关掉。
敏感数据保护 总开关 + 添加规则 总开关说明原文：「关闭后，下方数据检测规则全部不生效（规则仍保留，可先关着攒规则）。开启后规则随策略下发到成员客户端，命中时触发敏感信息确认弹框。」
生效范围 可 +部门 / +成员 逐条指定。给财务单独建策略，就是在这里选「财务部」。
基本信息 策略名称、描述、优先级（数字越大越高）、启用开关。
为什么这一页对财务最重要？
它是整个后台里唯一一个能真正落到「成员本机行为」上的管控点： 别的开关（模型、连接器、知识库）管的是「AI 能拿到什么」， 而沙箱策略管的是「AI 在你电脑上能碰什么、能发到哪去」。 财务的数据敏感度最高，这一页必须配。

4. 数据边界与合规

4.1 网络设置 · IP 白名单 /admin/setting/network

页面原话：「配置允许访问的 IP 网段，增强企业数据安全性；IP 白名单作用于代码助手客户端，被限制的 IP 将无法登录客户端并使用。」

规则（页面上写得很明确）：

  • 多个 IP 用英文逗号隔开，逗号前后不加空格；
  • 只填 127.0.0.1 = 禁止所有 IP 访问；
  • 不填 = 允许所有 IP（默认）；
  • 支持网段写法，如 10.10.10.0/24。

页面会显示「您当前 IP」并支持一键复制，方便把出口 IP 加进去。

对财务的用法：把白名单收窄到公司办公网出口 IP。 这样即使账号密码泄露、或员工离职后在家里/外面登录，也用不了客户端。
注意副作用：员工出差、居家办公也会被一起挡在外面——所以要么先确认公司是否有固定出口 IP，要么配合 VPN 使用。

4.2 分享与协作 /admin/client-config/share-collab

管「成员在客户端分享 / 协作时能对外到什么范围」。两项独立配置，保存后约 1 分钟在客户端生效。

项目可选项说明
发布范围 ① 仅支持组织内可见（推荐 · 默认）
② 支持组织内可见和全网可见 		①的组织外账号即便拿到链接也无法访问；②允许成员手动切到「全网可见」，但默认值仍是「仅组织内」。
协作范围 ① 仅支持组织内可见（推荐 · 默认）
② 支持组织内可见和全网可见 		同上逻辑，管的是「邀请谁一起协作」。①时组织外账号即使收到邀请也无法加入。
对财务：两项都必须选「仅支持组织内可见」。 页面特别提示了一句——即便开启「全网可见」，客户端默认仍为「仅组织内」，需成员手动切换。 也就是说，只要开了②，就存在成员自己把财报、客户名单发到公网的可能。财务场景不该留这个口子。

4.3 日志管理

页面能力
操作日志
/admin/log/list		 记录后台管理操作。字段：操作、操作内容、操作端、操作人、IP 地址、操作时间。支持按「今日 / 昨日 / 近3天 / 近7天」筛选。
这是「谁改了配置」的追溯依据。
对话日志
/admin/log/sessions		 页面定位：「记录团队成员与 AI 的完整对话，支持追踪使用情况与合规审计」。有一个「开启对话日志」总开关。
对话日志的三个必须知道的前置条件（页面原文）：
  1. 开启后自动记录所有对话；
  2. 关闭前已有的记录将被清除；
  3. 页面明确警告：「日志内容可能涉及代码、业务数据等敏感信息，请确认已获得相应授权并告知团队成员后再开启。」
换句话说，它是一把双刃剑：既是最好的审计手段，也是全员的对话留痕。 对财务这类敏感岗位，合规上往往需要开，但必须走「告知 + 授权」流程，否则触碰员工隐私，反而给自己埋雷。

5. 资源治理：控制成员能用哪些 AI 能力

这一块的作用是——不让成员自己乱接外部系统、乱装东西。几乎每一页都带一个「下发策略」和「可见范围」，逻辑一致：企业先建好，再决定发给谁。

页面适用产品关键能力
模型管理 — 23 个内置模型（混元、DeepSeek、GLM、Space-Bunny 等），每个可设「可见范围」和「可见端」（CodeBuddyIDE / CLI / WorkBuddy / CloudAgent / VSCode / JetBrains / VisualStudio）；支持「模型策略」「成员自定义模型」。
对财务：可以把模型收敛到少数几个，避免数据流向不明确的模型。
知识库 CodeBuddy 支持
WorkBuddy 暂不支持		 企业级知识库（自定义知识库 / 官方知识库）。
Skill 管理 三端 都支持 Skill 列表、分类管理、Skill 下发策略、成员自定义 Skill（内置 10000+）。
专家管理 WorkBuddy / 企业智能体 支持 专家列表、分类管理、专家下发策略、企业自建专家。
Connector 管理 WorkBuddy / 企业智能体 支持 连接外部服务（GitHub、Figma、腾讯文档等）。含 下发策略 + 成员自定义连接器开关。
对财务：这是「AI 能连到哪些外部系统」的总闸，比如能不能连 ERP、网银。
自定义指令 CodeBuddy 支持
WorkBuddy 暂不支持		 全局提示词（给全公司下统一的 AI 行为规范）。
Playbook — 20 个现成 Agent 范例（含数据分析师、ERP 报表分析、SRE 事件响应等），可一键导入。

企业智能体（Beta）

除了「给个人配能力」，企业还能自己造 Agent：

  • 快速开始：用自然语言描述需求，AI 自动生成 Agent 配置。自带模板——CRM 销售助手、ERP 报表分析（财务数据拉取、异常指标识别、月度经营报告生成）、代码评审助手等。
  • Agents：Agent = 模型 + 系统提示词 + 技能工具。分享给成员后，每个人打开都是独立 Session + 独立云端沙箱，对话与文件在该 Session 内持久保存。带「下发策略」。
  • Runtimes：Session 背后真正跑的云端沙箱（独立文件系统、进程、网络）。运维视角，状态有「运行中 / 休眠 / 失败」，用于排障。
  • 凭据管理：对财务很重要。凭据加密存储，Agent 调 MCP / Skill / 外部 API 时由代理层在运行时解密注入，不用在代码或配置里写明文密钥。
  • 自动化任务：设执行频率 + 提示词，到点自动跑，结果可投递到飞书 / 企微 / 钉钉 / QQ，也可在执行记录中追溯；单次最长 30 分钟，任务数不限。
  • 评测中心：评测/质量验证。

助理渠道设置 /admin/client-config/channel

一个「助理渠道总开关」（关闭后企业全部助理渠道不可用）+ 渠道清单，逐项可「编辑」（设可见范围、启用）：

微信助理(Bot)、微信客服号、企微助理、企业微信集成、QQ 机器人、钉钉、飞书。

开关变更即时生效，客户端约 5 分钟内同步。

客户端定制 /admin/client-config/custom

管 WorkBuddy 桌面端左侧导航的菜单：内置菜单（新建任务、助理、项目、专家·技能·连接器、定时任务、资料库、更多）由平台预置，可启停 / 排序 / 改显示名（中英文）/ 改图标，不可移除；还能通过 iframe 嵌入企业自有 Web 做自建菜单。整体编辑、整体发布。

可按部门单独定制菜单：比如给财务部门只留「助理 · 定时任务 · 资料库」，把研发向的入口收起来，界面更干净，上手更快。

6. 用量与成本控制

页面内容
订阅管理当前版本、订阅状态、到期时间、剩余天数；席位管理（全部 / 已授权 / 未授权 / 使用率，可变配席位）；月固定用量（固定额度 / 已使用 / 剩余 / 下次重置）；加量包（剩余用量、自动续购开关）。
抵扣顺序：按到期时间先后优先抵扣即将到期的用量。
成员用量 / 组织用量 / 应用用量 / 用量明细按成员、按组织、按应用维度看消耗，可下钻明细。
计量设置
/admin/setting/metering-settings		限量周期模式二选一：
① 默认（按订阅生效日切片）——从订阅生效日起每满 1 个月刷新已用量；
② 自然月（每月 1 日 00:00 刷新）——严格按自然月切片，与订阅生效日无关。
选②更好对账（财务口径天然就是自然月）。
对财务的用法：给财务部门单独设限量（成员/部门限量），既是成本控制，也是「用量异常」的预警手段—— 某个账号突然烧掉大量额度，往往说明用法跑偏或出了状况。

数据统计

研效看板（/admin/dashboard/panel）：活跃情况（活跃用户数、补全活跃、对话活跃）、对话指标（对话次数、使用指令次数、引用上下文次数、使用智能体/知识库次数）、补全指标（生成/采纳/采纳率）、代码生成指标（AI 生成行数、总新增行数、生成率）。支持按部门 / 客户端 / 插件版本分布，可「导出数据」。另有「明细数据」页。

7. 财务部门落地配置清单（推荐值）

把上面的东西收成一张「照做就行」的表。按优先级排序，1 是必做。

优先配置位置建议值为什么
1 客户端安全
新建「财务部」策略
优先级设为最高		 生效范围 = 财务部 多策略命中只生效优先级最高的那条，所以财务策略必须压在最上面，确保底线性。
1 └ 沙箱安全 →
允许对话内开启完全访问		 关闭 关掉后成员无法切「完全访问」，所有操作强制在沙箱约束内。这是整个后台最硬的一道锁。
1 └ 沙箱安全 →
安全规则（按路径）		 财务目录：
读=允许
写=询问或禁止
删除=禁止		 把「财务数据目录」「共享盘」单独列出来管，读写删分开控制。
1 分享与协作 发布范围 + 协作范围
都选「仅支持组织内可见」		 堵死「一键把财报/客户名单发布到公网」这条路。
2 └ 沙箱安全 →
命令规则（按前缀）		 禁用危险前缀，如
rm / del / curl / scp		 防止批量删除、防止把本地文件上传到外部。按前缀匹配，配置成本低。
2 └ 沙箱安全 →
网络访问		 「禁止全部对外访问」
+ 白名单只放开必要域名		 数据外传的最后一道闸。白名单外的域名一律拦截。
2 └ 数据安全 删除保护 开启
批量删除阈值 调低（如 3）		 误删/恶意删除要有拦阻和审批。
2 └ 敏感数据保护 总开关 开启
加规则：身份证号、银行卡号、金额等		 命中的时候会弹「敏感信息确认框」，等于给外发动作加一道人工确认。
2 网络设置 → IP 白名单 填写公司出口 IP / 网段 登录层锁死来源。离职、外网登录直接失效。
3 └ 内置运行时 按需关闭
（如关掉 Node.js / Python）		 财务日常不需要跑脚本，关掉等于少一整套执行能力。
3 综合管理 → 技能安装安全 开启（禁止装高风险技能） 技能是外部代码，是隐蔽的数据通道。
3 Connector 管理 → 下发策略 只下发财务需要的
（如腾讯文档）；关自定义		 管住「AI 能连哪些外部系统」。
3 模型管理 → 可见范围 只放开选定模型与端 避免数据流向不明确的模型。
3 计量设置 限量周期选「自然月」
+ 给财务设部门限量		 好对账；用量异常可预警。
3 管理员角色 财务一律「普通成员」
如需对接人，另建受限角色		 最小权限原则。
3 对话日志 按合规要求决定；
开启前走「告知 + 授权」		 审计需要，但涉及全员留痕，流程要合规。
3 客户端定制 给财务做一套精简菜单 降低认知负担，上手更快。

另：成员与部门数据来自「腾讯统一身份（OneID）」，后台只读；账号/组织维护要去 OneID 平台。「开放与集成 → API 管理」页已提示旧功能迁移到新版开放平台。
